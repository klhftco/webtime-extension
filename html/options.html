      Prevent disabling WebTime

      WebTime can block sites, but it cannot stop you from opening chrome://extensions and switching it off. Chrome's URLBlocklist policy can: it makes the Extensions page refuse to open, so turning WebTime off takes a deliberate detour instead of two clicks.

      This is friction, not security. Anyone with administrator access can undo it in one command — including you, later tonight. That is the point: it buys a pause, not a lock. See what this does not stop.

      Pick your platform

      Each path writes the same policy. You need administrator (or sudo) rights, and the policy applies to every Chrome profile on the machine.

      1. Open PowerShell as Administrator

        Press Win, type PowerShell, then choose Run as administrator.

      2. Write the policy

        This creates HKLM\SOFTWARE\Policies\Google\Chrome\URLBlocklist and adds one entry per blocked URL.

        $key = 'HKLM:\SOFTWARE\Policies\Google\Chrome\URLBlocklist'
New-Item -Path $key -Force | Out-Null
Set-ItemProperty -Path $key -Name '1' -Type String -Value 'chrome://extensions'
Set-ItemProperty -Path $key -Name '2' -Type String -Value 'chrome://extensions-internals'
Set-ItemProperty -Path $key -Name '3' -Type String -Value 'chrome://settings/extensions'

      3. Restart Chrome

        Quit every Chrome window and reopen it, then verify the policy.

      Undo on Windows 
      Remove-Item -Path 'HKLM:\SOFTWARE\Policies\Google\Chrome\URLBlocklist' -Recurse -Force

      1. Open Terminal

        Applications → Utilities → Terminal.

      2. Write the policy

        Chrome reads managed policy from the com.google.Chrome domain in /Library/Preferences.

        sudo defaults write /Library/Preferences/com.google.Chrome URLBlocklist -array \
  "chrome://extensions" \
  "chrome://extensions-internals" \
  "chrome://settings/extensions"

      3. Restart Chrome

        Quit Chrome completely (Cmd+Q, not just closing the window) and reopen it, then verify the policy.

      On a Mac managed by an employer or school, policies arrive through an MDM configuration profile and land in /Library/Managed Preferences. Those win over the file above — ask your administrator instead.

      Undo on macOS 
      sudo defaults delete /Library/Preferences/com.google.Chrome URLBlocklist

      1. Open a terminal

        You need sudo to write under /etc.

      2. Write the policy file

        Chrome reads every JSON file in /etc/opt/chrome/policies/managed/.

        sudo mkdir -p /etc/opt/chrome/policies/managed
sudo tee /etc/opt/chrome/policies/managed/webtime.json > /dev/null <<'JSON'
{
  "URLBlocklist": [
    "chrome://extensions",
    "chrome://extensions-internals",
    "chrome://settings/extensions"
  ]
}
JSON
sudo chmod 644 /etc/opt/chrome/policies/managed/webtime.json

      3. Restart Chrome

        Close every Chrome window and reopen it, then verify the policy.

      Using Chromium instead of Chrome? Use /etc/chromium/policies/managed/ for the same file.

      Undo on Linux 
      sudo rm /etc/opt/chrome/policies/managed/webtime.json

      Verify it took effect

      1. Open the policy page

        Paste chrome://policy into the address bar. Extension pages cannot link to chrome:// URLs, so it has to be pasted.

      2. Reload policies

        Click Reload policies. URLBlocklist should appear with status OK and your three entries.

      3. Try the Extensions page

        Paste chrome://extensions into the address bar. Chrome should show “Blocked Page — This page has been blocked by your administrator.”

      What this does not stop

      • Removing WebTime from the toolbar. Right-clicking the extension icon still offers Remove from Chrome, which never opens the Extensions page. Closing that hole needs the ExtensionSettings policy below.
      • Anyone with admin rights. The undo command is one line, and you have it.
      • A different browser. The policy is Chrome-specific; Firefox, Safari, and Edge are untouched.
      • Guest mode or a fresh OS user. Machine-level policy applies to all Chrome profiles, but a different machine or OS account is a different story.
      Stronger option: pin the extension with ExtensionSettings

      force_installed makes Chrome reinstall WebTime if it is removed and hides the disable and remove controls entirely. It requires the extension to be installed from the Chrome Web Store — it does not apply to an unpacked development load. This extension's ID is unknown.

      {
  "ExtensionSettings": {
    "__EXTENSION_ID__": {
      "installation_mode": "force_installed",
      "update_url": "https://clients2.google.com/service/update2/crx"
    }
  }
}

      Place this alongside URLBlocklist in the same policy location for your platform. Reversing it means editing policy again — treat it as a real commitment, not an experiment.

      Tracking mode

      Focused mode tracks only the active tab of the focused window. Visible windows mode tracks the active tab in each non-minimized browser window (useful for split-screen) and only counts a normalized domain once even if it appears in multiple windows. Chrome extensions cannot detect OS desktops, so for the most accurate tracking minimize windows or switch them to an untracked page (like the New Tab page) when moving them to another desktop.
